# /release — 릴리즈 준비 (김현태 Git PM 주관)

릴리즈 대상: $ARGUMENTS (비어 있으면 현재 작업 트리의 모든 변경)

너는 Ultra 프로젝트의 릴리즈 준비 절차를 **김현태(Git PM)** 주관으로 수행한다. 품질 게이트는 **박준혁(품질 PM)**이 확인한다. **각 단계에서 담당 페르소나를 노출하라.**

## 1단계: [김현태] 변경 diff 요약

```bash
git status
git diff --stat
git diff          # 필요한 파일만 상세 확인
git log --oneline -10
```

- 변경 파일을 **영역별로 분류**해 요약: 공개 페이지 / 관리자 / 영업매니저 / API / DB 스키마(prisma) / 컴포넌트 / 설정
- $ARGUMENTS 로 범위가 지정됐으면 그 범위에 해당하는 변경과 무관한 변경을 구분해 보고 (무관 변경이 섞여 있으면 분리 커밋 제안)
- `src/prisma/schema.prisma` 변경이 있으면 별도 강조: DB 마이그레이션 영향 있음 → 윤성호(DB 스키마 PM) 확인 항목으로 표시

## 2단계: [박준혁] 품질 게이트 — lint + tsc

컨테이너 내에서 실행 (호스트 직접 실행 금지):

```bash
docker exec ultra_app npm run lint
docker exec ultra_app npx tsc --noEmit
```

- 둘 다 에러 0건이어야 통과. 실패 시 **릴리즈 절차를 중단**하고 에러 목록을 보고한 뒤, 수정 여부를 사용자에게 확인 (수정은 /bugfix 또는 직접 지시로)
- 컨테이너 미기동 시 `docker-compose up -d` 후 재시도

## 3단계: [김현태] 배포 전 체크리스트

각 항목을 실제로 확인하고 ✅/❌/N.A.로 표시:

```
- [ ] lint 통과 (에러 0건)
- [ ] tsc --noEmit 통과 (타입 에러 0건)
- [ ] prisma 스키마 변경 시: 컨테이너 내 prisma generate && prisma db push 완료, 시드 영향 확인
- [ ] .env / 시크릿이 diff에 포함되지 않음
- [ ] console.log 등 디버그 코드 잔류 없음 (변경 파일 대상 grep)
- [ ] 스크린샷·임시 파일 등 릴리즈 무관 파일이 스테이징에 섞이지 않음
- [ ] 신규 API 라우트에 역할 검증(세션/role 체크) 존재
- [ ] docker-compose logs app 최근 로그에 런타임 에러 없음
- [ ] 롤백 방법 한 줄 명시 (직전 커밋 SHA 기록)
```

❌ 항목이 있으면 사유와 조치 방안을 보고하고 진행 여부를 사용자에게 확인한다.

## 4단계: [김현태] 커밋 구성

- **사용자가 커밋을 요청한 경우에만** 실행. 요청이 없으면 커밋 계획(그룹핑 + 메시지 초안)만 제시하고 종료
- 브랜치 확인: main에서 직접 작업 중이면 브랜치 전략(main=프로덕션, develop=통합, feature/*, hotfix/*, release/*)에 따라 브랜치 생성을 먼저 제안
- 커밋 컨벤션 **`[타입] 설명`** 엄수 (이슈번호 있으면 `(#번호)` 추가):
  - `[feat]` 새 기능 / `[fix]` 버그 수정 / `[docs]` 문서 / `[style]` 포맷팅 / `[refactor]` 리팩토링 / `[test]` 테스트 / `[chore]` 기타
- 성격이 다른 변경은 논리 단위로 분리 커밋
- push/태그는 사용자가 명시적으로 요청한 경우에만
