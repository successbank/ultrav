# PR Description From Diff

git diff를 근거로 리뷰어가 바로 판단할 수 있는 PR 본문을 작성하는 스킬.

## 절차

1. **diff 수집** — `git diff <base>...HEAD --stat` 및 전체 diff 확인. base 브랜치가 불명확하면 `main` 기준
2. **변경 분류** — 기능 추가 / 버그 수정 / 리팩토링 / 스키마 변경 / 설정 변경으로 구분
3. **본문 작성** — 아래 섹션 구성으로 작성. 커밋 메시지 컨벤션(`[타입] 설명 (#이슈번호)`)과 일치하는 제목 제안

## PR 본문 섹션

```
## 무엇을, 왜
- 변경 목적과 배경 (관련 PRD/이슈 링크)

## 변경 요약
- 파일별 핵심 변경 (라우트/컴포넌트/API/스키마 구분)

## 테스트
- 추가한 테스트 / 수행한 수동 검증 시나리오 (역할별: USER/HOSPITAL/SALES_MANAGER/ADMIN)

## 위험·롤백
- 영향 범위 (특히 prisma/schema.prisma, middleware, auth 변경 여부)
- 롤백 방법 (revert 가능 여부, 스키마 변경 시 롤백 절차)

## 체크리스트
- [ ] lint 통과
- [ ] 로컬(docker) 동작 확인
- [ ] 스키마 변경 시 DB 일관성 검토(윤성호/배지영) 완료
- [ ] 코드 컨벤션 검토(정대훈) 완료
```

## 주의

- diff에 없는 내용을 추측해서 쓰지 말 것 — 근거는 항상 실제 변경 라인
- 스키마/인증/미들웨어 변경이 포함되면 위험 섹션에 반드시 강조
