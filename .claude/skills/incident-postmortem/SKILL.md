# Incident Postmortem

P0/P1 인시던트의 blameless(비난 없는) 사후 보고서를 작성하는 스킬. 사람이 아닌 시스템·프로세스의 결함에 집중한다.

## 절차

1. **사실 수집** — 로그(`docker-compose logs app`), git 이력, 대화 기록에서 객관적 사실만 추출. 추측은 "미확인"으로 표기
2. **템플릿 작성** — 아래 구조로 보고서 작성
3. **저장** — `docs/incidents/<날짜>-<제목>.md` 형식으로 저장 (예: `docs/incidents/2026-07-08-quote-pdf-encoding.md`)

## 보고서 템플릿

```
# [인시던트 제목]

- 발생일시 / 감지일시 / 복구일시 (타임존 명시)
- 심각도: P0/P1/P2
- 작성일:

## 타임라인 (객관적 사실만)
- HH:MM 사건 → 조치

## 영향
- 영향받은 사용자 역할·기능 범위 (주문/견적/결제 등 금전 영향 별도 명시)
- 지속 시간

## 근본 원인 (5-Why)
- why1 ~ why5

## 액션 아이템
- 즉시 (완료됨): ...
- 중기 (1-2주): ...
- 장기 (구조 개선): ...

## 학습 사항
- 잘 된 것 / 아쉬운 것 / 운이 좋았던 것

## 회귀 테스트 제안
- 동일 장애 재발을 감지할 테스트 시나리오 (입력 → 기대 결과)
```

## 원칙

- **blameless** — "누가"가 아니라 "무엇이 이것을 가능하게 했는가"를 묻는다
- 액션 아이템에는 담당(페르소나 팀)과 기한을 붙인다
- DB 관련 장애면 백업/복구 절차 점검을 액션 아이템에 포함
