# Bugfix RCA

버그를 증상 치료가 아닌 근본 원인 수준에서 수정하기 위한 스킬.

## 절차

1. **재현 확인** — 버그를 재현하는 최소 조건(사용자 역할, 라우트, 입력값)을 특정한다. 재현 불가 시 로그(`docker-compose logs -f app`)와 관련 코드를 먼저 조사
2. **5-Why RCA** — why1(직접 증상)부터 why5(근본 원인)까지 인과 사슬을 명시적으로 기록
3. **최소 변경 패치** — 근본 원인만 겨냥한 최소 diff 작성. 리팩토링 욕심 금지 (필요하면 별도 후속 작업으로 제안)
4. **회귀 테스트 추가 제안** — 동일 버그의 재발을 감지할 테스트 케이스를 제안한다. 자동화 테스트가 어려우면 수동 검증 시나리오(입력 → 기대 결과)라도 문서화
5. **유사 패턴 탐색** — 동일 클래스의 버그가 코드베이스 다른 곳에 있는지 grep으로 확인하고, 발견 시 후속 수정 후보로 보고

## 산출물 형식

```
## RCA
- why1: ...
- why2: ...
- why3: ...
- why4: ...
- why5 (근본 원인): ...

## 수정 내용
- 파일: 변경 요약 (최소 diff)

## 회귀 테스트 제안
- 시나리오: 입력 → 기대 결과

## 유사 패턴
- 발견 위치 / 없음
```

## 주의

- 수정 후 반드시 실제 동작 확인 (컨테이너 핫리로드 반영 후 해당 화면/API 검증)
- Prisma 스키마 관련 버그면 일관성 검토(윤성호/배지영) 대상임을 보고에 명시
