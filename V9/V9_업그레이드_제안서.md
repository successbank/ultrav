## 0. 한 줄 가치

> V8이 **"루프로 끝까지 돌리고, 안드로이드 네이티브까지 AI가 주도한다 — 예산과 정지선 안에서"** 였다면,
> V9은 그 루프를 **하네스(harness)에 얹어 더 오래·더 안전하게** 돌린다 — **스스로 컨텍스트를 관리하고(CONTEXT) · 헛돌면 멈추고(PROGRESS) · 틀리면 기억한다(REFLECT).**

V9 = **V8의 모든 것(3-레이어 · 5트랙 · 31팀 · 크로스플랫폼 · 루프 F · 안드로이드 G · 드롭인 H)을 보존·계승** + **루프 엔지니어링 2.0(트랙 F⁺)**.
요청(루프 엔지니어링 적용)을 V8의 기존 루프 자산과 **융합**해, "루프를 정식화한 V8"을 "루프를 하네스 등급으로 운영하는 V9"으로 끌어올린다.

V8은 루프를 **정식화**했으나, 루프가 **길고 자율적으로** 돌 때의 운영 실패(2026 현장에서 드러난)는 아직 미봉이었다.

| # | 갭 | 영향 | V9 해결 |
|---|---|---|---|
| **G19** | **실행 중 컨텍스트 폭주/패닉** — 긴 루프가 컨텍스트 창을 넘쳐 모델이 마무리를 서두르고 품질을 깎음 | 장시간 루프 후반 품질 급락 | **CONTEXT 규율** + `loop-context-compact.sh` + eval `context-compaction` |
| **G20** | **헛도는 루프 미감지** — 반복은 도는데 지표가 안 변해도 상한까지 비용 소모 | 무의미한 토큰·비용 낭비 | **PROGRESS 규율(무진행 감지)** + `loop-no-progress-check.sh` + STOP `no_progress_ticks` + eval `no-progress-stop` |
| **G21** | **루프 간 학습 부재(기억상실)** — 같은 실수를 매 루프 처음부터 반복 | 수렴 느림·반복 실패 | **REFLECT 규율(Reflexion)** + `loop-reflector` + `010_loop_lessons` + MCP `loop_lesson_*` + eval `reflection-memory` |

## 4. V9 업그레이드 — 트랙 F⁺ (루프 엔지니어링 2.0)

6요소(구조)는 그대로, **3 운영 규율(어떻게 오래 잘 도는가)** 과 **패턴·하네스** 를 더한다.

### 4-1. 3 운영 규율 (신규)
- **CONTEXT(컨텍스트 위생)** — 매 tick 압축·외부화·선별 주입. 플랜·누적치는 컨텍스트가 아닌 변수/DB에. → `loop-context-compact.sh`
- **PROGRESS(무진행 감지)** — 지표 델타가 N tick 무개선이면 종료(상한과 별개). → `loop-no-progress-check.sh`, STOP `no_progress_ticks>=N`
- **REFLECT(리플렉션 기억)** — 실패에서 언어 교훈을 추출해 `loop_lessons`에 적재, 다음 tick/루프 시작 시 재주입(Reflexion). 루프 **도중** 학습(↔ `loop-postmortem`은 루프 **이후**). → `loop-reflector`, `loop-reflect`

### 4-2. 루프 패턴 라이브러리 (신규)
ReAct · Plan-and-Execute · Evaluator-Optimizer(grade-revise) · Reflexion · fan-out · 조합형 — 목적별 선택 기준 + 6요소 기본값. → `루프_패턴_라이브러리.md`, `loop-pattern-select`

### 4-3. 하네스 5계층 배치 (신규)
도구 오케스트레이션 · 검증 루프 · 컨텍스트&메모리 · 가드레일 · 관찰성 — V7/V8 자산을 5계층에 매핑. → `하네스_엔지니어링_가이드.md`

### 4-4. Claude Code 2026 매핑 보강
`/goal`(완료조건, 매 턴 끝 평가 모델 점검) ↔ STOP·loop-grader·loop-tick-stop-check. **control-before-autonomy 사다리**(인터랙티브 → grade-revise → 백그라운드 자율 → 다중에이전트)로 통제를 먼저 채우고 자율 단계를 올린다.

### 4-5. 카탈로그 확장
재사용 루프 6종 → **8종**(+⑦ Reflexion 학습 루프, +⑧ 멀티에이전트 오케스트레이션 루프). ①~⑥에도 `no_progress`·context·reflect 공통 강화.

## 7. 예상 성과 (정량 가설)

- 장시간 루프 후반 품질 저하(컨텍스트 패닉): CONTEXT 위생으로 **체감 완화**
- 헛도는 루프 비용: 무진행 감지로 낭비 tick **−50%+** (상한 도달 전 조기 종료)
- 반복 실패 수렴: Reflexion 교훈 재주입으로 동일 실패 재발 **감소**
- 부적합 루프 선택: 패턴 라이브러리로 설계 시행착오 **감소**
- (계승) 자율 비용 사고: BUDGET/STOP 상한 내 **100% 억제** 유지

> 수치는 가설이며 `loop_runs`·`loop_lessons` 적재 후 `loop-postmortem`으로 실측·교정한다.

## 9. 결론

V8은 루프를 **정식화**했고, V9은 그 루프를 **운영 등급(하네스)** 으로 올린다.
V9의 한 줄: **"루프를 하네스에 얹어 — 짧게 보고(CONTEXT), 헛돌면 멈추고(PROGRESS), 틀리면 기억한다(REFLECT) — 예산과 정지선, 그리고 통제가 먼저인 자율로."**

가장 먼저 손댈 단 하나: 기존 루프 1종에 **`loop-no-progress-check.sh` + `loop-context-compact.sh`** 를 붙이고 env:dev에서 1회 실행해 `loop_runs`로 효과를 확인 → 이어 `loop-reflector`로 교훈 누적.
