# 루프 설계 체크리스트

새 루프를 만들 때 이 표를 위에서 아래로 통과해야 한다. 하나라도 ✗면 실행하지 않는다.

## 1. 6요소 완비
| # | 점검 | 통과 기준 |
|---|---|---|
| 1 | TRIGGER가 명시됐나 | 구체적 이벤트/스케줄(예: `ci.failed`, `0 2 * * *`). "항상"은 금지 |
| 2 | SCOPE가 한정됐나 | repo·경로·env가 좁게 지정. 무제한 범위 금지 |
| 3 | ACTION이 측정 가능한가 | "개선" 같은 모호 표현 대신 검증 가능한 행동 |
| 4 | BUDGET 상한을 명시했나 | tick당 + 누적 두 층(토큰·비용·반복·시간 중 최소 2종) |
| 5 | STOP이 결정적인가 | 목표 OR 횟수 OR 예산 OR 시간의 OR 결합, yes/no 판정 가능 |
| 6 | REPORT 수신자를 정했나 | Slack 채널/PR/`loop_runs` 중 최소 1곳 |

## 2. 안전 게이트
| # | 점검 | 통과 기준 |
|---|---|---|
| 7 | 비가역 행동에 사람 승인 게이트가 있나 | merge·revert·prod 배포·삭제 앞에 `human_gate` |
| 8 | 결정적 판정을 hook으로 강제하나 | STOP/BUDGET 판정을 LLM이 아닌 hook(exit 0/1)으로 |
| 9 | fan-out 깊이/동시성 상한이 있나 | 서브에이전트 깊이·동시 개수 상한, 리드만 fan-out |
| 10 | dry-run을 먼저 도나 | 첫 실행은 `env: dev`, 낮은 BUDGET |
| 11 | grade-revise 루브릭이 명확한가 | 채점 기준이 객관적이고 통과선이 숫자/조건으로 정의 |
| 12 | 종료 후 기록이 남나 | `loop_runs` 적재(반복·토큰·비용·정지사유·결과) |
| 13 | (V9) 컨텍스트 위생이 있나 | 매 tick 압축·외부화·선별주입(`loop-context-compact.sh`) |
| 14 | (V9) 무진행 감지가 있나 | 지표 델타 N tick 무개선 시 STOP(`loop-no-progress-check.sh`) |
| 15 | (V9) 리플렉션 기억을 쓰나 | 실패 교훈 `loop_lessons` 적재·주입(`loop-reflector`) |

## 3. STOP 결정성 자가질문
- 정지조건을 사람이 보지 않고 **코드로 true/false** 판정할 수 있는가? (못 하면 다시 설계)
- 목표가 영원히 충족 안 될 경우의 **상한**(횟수·예산·시간)이 있는가?
- 목표 달성 판정을 grader/hook이 하는가, 아니면 LLM이 "됐다"고 말하는가? (후자면 false done 위험)

## 4. "위험한 루프" 경고
| 위험 | 신호 | 즉시 조치 |
|---|---|---|
| **무한루프** | STOP에 횟수·예산·시간 상한이 없음 | OR 상한 추가 전까지 실행 금지 |
| **비용 폭발** | BUDGET이 한 층(예: 반복만)뿐 | 토큰·비용 누적 상한 추가, `loop-budget-cap.sh` 연결 |
| **자가증식(runaway fan-out)** | 서브에이전트가 또 서브에이전트를 생성 | 깊이=1로 제한, 리드만 분배 권한 |
| **거짓 완료(false done)** | 검증 없이 "완료" 선언 | 완료를 hook/grader 판정으로만 인정 |
| **범위 이탈** | SCOPE 밖 파일/레포 변경 흔적 | SCOPE를 경로 화이트리스트로 좁히고 hook으로 차단 |
| **헛도는 루프(no progress)** | 반복은 도는데 지표가 안 변함 | 델타 감지 `loop-no-progress-check.sh` STOP 추가 |
| **컨텍스트 폭주/패닉** | 창이 차며 마무리를 서두름 | 매 tick 압축·외부화(`loop-context-compact.sh`) |
| **기억상실(반복 실수)** | 과거 실패를 매번 다시 함 | REFLECT: `loop_lessons` 적재·주입 |
| **조용한 실패** | REPORT 없이 종료 | REPORT 필수화, 종료 hook에서 강제 |

## 5. 출시 전 최종 확인(요약)
1. 6요소 6개 전부 ✓
2. STOP = 결정적 OR 결합 ✓
3. BUDGET = tick당 + 누적 ✓
4. REPORT 수신자 ≥ 1 ✓
5. 비가역 행동에 human_gate ✓
6. env:dev dry-run 완료 ✓
7. (V9) 컨텍스트 위생·무진행 감지 연결 ✓
8. (V9) 리플렉션 기억(`loop_lessons`) 연결 ✓

위 항목이 모두 ✓일 때만 prod 트리거에 연결한다.
