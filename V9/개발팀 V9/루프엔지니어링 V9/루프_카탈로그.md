# 루프 카탈로그 — 즉시 재사용 루프 6종

각 루프는 6요소 표 + 복사용 `loop spec`(YAML)로 구성된다. repo·예산·정지조건만 바꿔 바로 쓴다.
loop spec 스키마는 `loop-design` 스킬 산출물과 동일하다.

---

## ① PR-그린 루프 (CI 실패 → 수정 반복)
| 요소 | 값 |
|---|---|
| TRIGGER | 내 PR에 CI 실패 이벤트 발생 시 |
| SCOPE | 내가 연 PR의 변경 파일 + 직접 의존 모듈만 |
| ACTION | 실패 로그 분석 → 최소 수정 → 재push → CI 재실행 |
| BUDGET | tick당 30k 토큰 / 누적 $3 / 최대 8회 |
| STOP | CI 전부 green **OR** 8회 반복 **OR** $3 소진 |
| REPORT | PR 코멘트 + Slack `#eng-bots` 요약 + `loop_runs` 적재 |

```yaml
name: pr-green-loop
trigger: { on: ci.failed, scope_filter: "author:me" }
scope: { repos: [flipbook], paths: ["changed-files", "direct-deps"], env: dev }
action: "분석→최소수정→push→CI 재실행"
budget: { tokens_per_tick: 30000, cost_usd_max: 3, max_iterations: 8 }
stop: { any_of: [all_ci_green, iterations>=8, cost_usd>=3] }
report: { to: ["pr-comment", "slack:#eng-bots"], sink: loop_runs }
grade: { enabled: false }
```

## ② 테스트-커버리지 상향 루프
| 요소 | 값 |
|---|---|
| TRIGGER | 수동 시작 또는 주 1회(월요일 09:00) |
| SCOPE | repo `flipbook` 중 커버리지 70% 미만 파일만 |
| ACTION | 미커버 분기 식별 → 테스트 추가 → 커버리지 재측정 |
| BUDGET | tick당 서브에이전트 3개 / 40k 토큰 / 누적 $5 / 최대 12회 |
| STOP | 대상 파일 전부 ≥80% **OR** 12회 **OR** $5 |
| REPORT | 커버리지 전후 표 + Slack `#eng-bots` + `loop_runs` |

```yaml
name: coverage-raise-loop
trigger: { on: schedule, cron: "0 9 * * MON" }
scope: { repos: [flipbook], filter: "coverage<70%", env: dev }
action: "미커버 분기→테스트 추가→재측정"
budget: { subagents_per_tick: 3, tokens_per_tick: 40000, cost_usd_max: 5, max_iterations: 12 }
stop: { any_of: ["coverage>=80%", iterations>=12, cost_usd>=5] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [coverage_before_after] }
grade: { enabled: true, rubric: "신규 테스트가 실제 분기를 커버하고 통과하는가" }
```

## ③ 버그 RCA → 골든케이스 승격 루프
| 요소 | 값 |
|---|---|
| TRIGGER | `errors.new` 발행(프로덕션 새 에러) |
| SCOPE | 해당 에러의 재현 경로 + 관련 모듈 |
| ACTION | 재현 → 5-Why RCA → 최소 수정 → 회귀 테스트 → eval 골든 후보 |
| BUDGET | tick당 50k 토큰 / 누적 $4 / 최대 6회 |
| STOP | 재현 테스트 green + 골든 후보 생성 **OR** 6회 **OR** $4 |
| REPORT | RCA 요약 + 골든 후보 경로 + Slack `#eng-bots` + `loop_runs` |

```yaml
name: bug-rca-golden-loop
trigger: { on: errors.new }
scope: { paths: ["repro-path", "related-modules"], env: dev }
action: "재현→5Why→최소수정→회귀테스트→eval 골든 후보"
budget: { tokens_per_tick: 50000, cost_usd_max: 4, max_iterations: 6 }
stop: { any_of: [repro_test_green_and_golden_created, iterations>=6, cost_usd>=4] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [rca_summary, golden_path] }
grade: { enabled: true, rubric: "수정이 근본원인을 제거하고 회귀 테스트가 실패→통과로 바뀌는가" }
human_gate: { before: merge }   # 머지는 사람 승인
```

## ④ 야간 리팩토링/의존성 루프
| 요소 | 값 |
|---|---|
| TRIGGER | 매일 02:00(야간 배치) |
| SCOPE | repo `flipbook`의 dev 의존성 + 안전 리팩토링 대상(순환 import 등) |
| ACTION | 의존성 minor/patch 업그레이드 → 빌드/테스트 → 통과분만 PR 생성 |
| BUDGET | tick당 서브에이전트 5개 / 60k 토큰 / 누적 $5 / 최대 10회 |
| STOP | 처리 대상 소진 **OR** 10회 **OR** $5 **OR** 04:00 경과 |
| REPORT | 생성 PR 목록 + 실패 항목 + Slack `#eng-bots` + `loop_runs` |

```yaml
name: nightly-refactor-deps-loop
trigger: { on: schedule, cron: "0 2 * * *" }
scope: { repos: [flipbook], targets: [dev-deps-minor-patch, safe-refactors], env: dev }
action: "업그레이드→빌드/테스트→통과분만 PR"
budget: { subagents_per_tick: 5, tokens_per_tick: 60000, cost_usd_max: 5, max_iterations: 10, wall_clock_until: "04:00" }
stop: { any_of: [targets_exhausted, iterations>=10, cost_usd>=5, "time>=04:00"] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [created_prs, failed_items] }
grade: { enabled: true, rubric: "업그레이드 후 빌드·테스트가 모두 통과하는가" }
human_gate: { before: merge }
```

## ⑤ eval 회귀 감시 루프
| 요소 | 값 |
|---|---|
| TRIGGER | `eval.regression` 발행 또는 main 머지 후 |
| SCOPE | 회귀 발생 카테고리의 골든 케이스 |
| ACTION | 회귀 케이스 재현 → 원인 커밋 bisect → 수정/롤백 제안 → eval 재실행 |
| BUDGET | tick당 40k 토큰 / 누적 $4 / 최대 8회 |
| STOP | 해당 eval 점수 ≥ baseline **OR** 8회 **OR** $4 |
| REPORT | bisect 결과 + 점수 회복 표 + Slack `#eng-bots` + `loop_runs` |

```yaml
name: eval-regression-watch-loop
trigger: { on: eval.regression }
scope: { category: "regressed-only", env: dev }
action: "재현→bisect→수정/롤백 제안→eval 재실행"
budget: { tokens_per_tick: 40000, cost_usd_max: 4, max_iterations: 8 }
stop: { any_of: ["score>=baseline", iterations>=8, cost_usd>=4] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [bisect_result, score_recovery] }
grade: { enabled: true, rubric: "제안 적용 후 eval 점수가 baseline 이상으로 회복되는가" }
human_gate: { before: revert-on-main }
```

## ⑥ 안드로이드 빌드-그린 루프 (`./gradlew`)
| 요소 | 값 |
|---|---|
| TRIGGER | Android 모듈 변경 push 또는 CI 빌드 실패 |
| SCOPE | 변경된 Gradle 모듈 + 직접 의존 모듈만 |
| ACTION | `./gradlew :app:assembleDebug test` 실행 → 실패 분석 → 수정 → 재빌드 |
| BUDGET | tick당 50k 토큰 / 누적 $5 / 최대 8회 / tick당 10분 |
| STOP | `assembleDebug` + 단위테스트 green **OR** 8회 **OR** $5 |
| REPORT | 빌드 로그 요약 + 수정 diff + Slack `#eng-bots` + `loop_runs` |

```yaml
name: android-build-green-loop
trigger: { on: [push, ci.failed], match: "android-module-changed" }
scope: { repos: [flipbook-android], targets: [changed-gradle-modules, direct-deps], env: dev }
action: "./gradlew :app:assembleDebug test → 실패분석 → 수정 → 재빌드"
budget: { tokens_per_tick: 50000, cost_usd_max: 5, max_iterations: 8, tick_timeout_min: 10 }
stop: { any_of: [assemble_and_unit_green, iterations>=8, cost_usd>=5] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [build_log_summary, fix_diff] }
grade: { enabled: true, rubric: "assembleDebug와 단위테스트가 모두 통과하는가" }
commands:
  build: "./gradlew :app:assembleDebug"
  test:  "./gradlew test"
```

## ⑦ Reflexion 학습 루프 (실패→교훈→재시도, V9 신규)
| 요소 | 값 |
|---|---|
| TRIGGER | 같은 류 작업 재실행 또는 grade-revise 2회 연속 실패 |
| SCOPE | 대상 작업 + 관련 `loop_lessons`(같은 loop_name·태그) |
| ACTION | 시작 시 관련 교훈 주입 → 실행 → 실패 시 "무엇이·왜·다음엔" 교훈 적재 → 재시도 |
| BUDGET | tick당 40k 토큰 / 누적 $4 / 최대 6회 |
| STOP | grader pass **OR** 6회 **OR** $4 **OR** 무진행 3tick |
| REPORT | 적용 교훈·신규 교훈 목록 + Slack `#eng-bots` + `loop_runs` |

```yaml
name: reflexion-learning-loop
trigger: { on: [manual, grade.failed_twice] }
scope: { task: "<대상>", memory: { store: loop_lessons, match: "loop_name+tags" } }
action: "관련 교훈 주입→실행→실패 시 교훈 적재→재시도"
budget: { tokens_per_tick: 40000, cost_usd_max: 4, max_iterations: 6 }
stop: { any_of: [grader_pass, iterations>=6, cost_usd>=4, no_progress_ticks>=3] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [applied_lessons, new_lessons] }
grade: { enabled: true, rubric: "<객관적 통과선 + 금지조건>" }
reflect: { enabled: true, agent: loop-reflector, sink: loop_lessons }
```

## ⑧ 멀티에이전트 오케스트레이션 루프 (fan-out + grade-revise + reflect, V9 신규)
| 요소 | 값 |
|---|---|
| TRIGGER | 대규모 작업 수동 시작(대량 리팩토링·멀티파일 수정) |
| SCOPE | 워커별로 분할된 파일 집합(겹치지 않게) + env:dev |
| ACTION | 리드가 작업 분할 → 워커 병렬 실행 → grader 채점 → 미달분 교훈 적재 후 재분배 |
| BUDGET | 동시 워커 ≤ 8 / 깊이=1 / tick당 80k 토큰 / 누적 $12 / 최대 8회 |
| STOP | 전 작업 pass **OR** 8회 **OR** $12 **OR** 무진행 2tick **OR** 사람 중단 |
| REPORT | 처리/실패 항목 + 적용 교훈 + Slack `#eng-bots` + `loop_runs` |

```yaml
name: multiagent-orchestration-loop
trigger: { on: manual }
scope: { repos: [flipbook], partition: "non-overlapping-files", env: dev }
action: "분할→워커 병렬→grader 채점→미달분 교훈 적재 후 재분배"
budget: { max_concurrent_workers: 8, fanout_depth: 1, tokens_per_tick: 80000, cost_usd_max: 12, max_iterations: 8 }
stop: { any_of: [all_tasks_pass, iterations>=8, cost_usd>=12, no_progress_ticks>=2, human_abort] }
report: { to: ["slack:#eng-bots"], sink: loop_runs, include: [done_items, failed_items, applied_lessons] }
grade: { enabled: true, rubric: "각 워커 산출이 통과선 충족 + 금지조건 위반 없음" }
reflect: { enabled: true, agent: loop-reflector }
human_gate: { before: merge }
safety: { only_lead_can_fanout: true }   # 자가증식 방지
```

> ⑦⑧은 V9 신규(REFLECT·fan-out). ①~⑥에도 V9 공통 강화를 권장: STOP에 `no_progress_ticks` 추가, tick 경계 `loop-context-compact.sh`, 반복 실패 시 `reflect: {enabled: true}`.

## 카탈로그 사용 요령
- 6요소 중 **STOP·BUDGET**은 반드시 환경에 맞게 재설정한다(기본값은 보수적 안전치).
- 운영 환경(prod)에 돌리기 전 항상 `env: dev`에서 1회 dry-run.
- merge·revert 같은 비가역 행동에는 `human_gate`를 둔다.
- 모든 루프는 종료 시 `loop_runs`에 적재되어 `loop-postmortem`의 분석 대상이 된다.
