# 루프 패턴 라이브러리 (V9 신규)

> "어떤 루프 **형태**를 쓸까"를 고르는 카탈로그. 6요소(`루프엔지니어링_방법론.md` §4)가 *무엇을* 채울지라면, 패턴은 *어떤 모양으로* 돌릴지다.
> 스킬 `loop-pattern-select`가 목적을 받아 아래에서 추천한다.

## 패턴 선택 빠른 표
| 상황/목적 | 추천 패턴 | 이유 |
|---|---|---|
| 한 작업 안에서 추론·도구를 번갈아 | **ReAct** | 가장 단순, 짧은 작업에 충분 |
| 길고 다단계라 드리프트가 걱정 | **Plan-and-Execute** | 계획/실행 분리로 표류 감소 |
| 품질 게이트가 필요 | **Evaluator-Optimizer (grade-revise)** | 생성자/평가자 역할 분리 |
| 같은 실수를 반복함 | **Reflexion (reflect)** | 실패를 언어 교훈으로 기억 |
| 대량·멀티파일 일괄 처리 | **fan-out (orchestrator-worker)** | 병렬로 처리량 확보 |
| 위 여러 개가 동시에 필요 | **조합형** | 예: fan-out + grade-revise + reflect |

---

## 1. ReAct (Reason + Act)
- **개념**: 추론(Reason) 한 스텝과 행동(Act, 도구호출) 한 스텝을 번갈아, 결과를 관찰하고 다음을 결정.[^1]
- **언제**: 단일·짧은 작업. 정지/예산이 단순(몇 스텝).
- **6요소 기본값**: ACTION=추론↔도구 교대 · STOP=목표 OR 소수 반복상한 · BUDGET 작게.
- **주의**: 작업 경계·정지·예산 개념이 약함 → 길어지면 다음 패턴으로.

## 2. Plan-and-Execute
- **개념**: **Planner**가 목표를 순서 있는 단계로 분해, **Executor**가 단계를 실행. 긴 다단계에서 표류(drift)를 줄인다.[^2]
- **언제**: 단계가 많고 순서 의존이 있는 작업(마이그레이션, 멀티스텝 기능).
- **6요소 기본값**: ACTION=계획 단계별 실행 · SCOPE=단계별 파일 한정 · STOP=모든 단계 완료 OR 상한.
- **연결**: 계획은 **컨텍스트가 아니라 변수/파일**로 외부화(CONTEXT 규율).

## 3. Evaluator-Optimizer (= grade-revise)
- **개념**: 한 LLM이 산출(Optimizer/Actor), **별도** LLM이 기준으로 채점(Evaluator). 역할이 **명시적으로 분리**된 점이 단일-LLM Reflection과 다르다.[^6]
- **언제**: 품질 통과선이 분명한 코드 생성/수정.
- **6요소 기본값**: ACTION=생성→채점→미달시 수정 반송 · STOP=pass=true OR 반복상한.
- **자산**: `loop-grader`(`{score,pass,feedback}` 계약), eval `grader-rubric`. 루브릭은 반증가능·이진 판정(`완료조건_가이드.md`).

## 4. Reflexion (reflect, 자기성찰 + 에피소드 메모리)
- **개념**: Actor(행동)·Evaluator(점수)·**Self-Reflection**(언어 교훈을 메모리에 기록)의 3역할. 교훈을 다음 시도에 주입해 점진 개선.[^6]
- **언제**: 같은 류의 실패가 반복되거나, 루프를 여러 번 재실행하는 경우.
- **6요소 + REFLECT 규율**: 실패 시 `loop_lessons`에 "무엇이·왜·다음엔" 적재 → 시작 시 관련 교훈 주입.
- **자산**: 에이전트 `loop-reflector`, 스킬 `loop-reflect`, DB `010_loop_lessons.sql`, MCP `loop_lesson_record`/`loop_lesson_search`.
- **차이**: REFLECT는 **루프 도중** 학습, `loop-postmortem`은 **루프 이후** 분석.

## 5. fan-out (Orchestrator-Worker)
- **개념**: 리드(Orchestrator)가 일을 쪼개 수십~수백 워커에 병렬 분배 후 결과를 모은다(Claude Code Dynamic Workflows).[^3]
- **언제**: 대규모 리팩토링, 멀티파일 일괄 수정, 대량 테스트 생성.
- **6요소 기본값**: BUDGET=동시성·깊이 상한(깊이=1, 리드만 분배) · SCOPE=워커별 파일 분할.
- **안전**: 자가증식 방지(워커가 또 워커 생성 금지), 플랜은 변수로 외부화.

## 6. 조합형 (V9 권장 기본)
실무 루프는 대개 합쳐진다.

| 조합 | 모양 | 쓰임 |
|---|---|---|
| **fan-out + grade-revise** | 병렬 생성 → grader가 미달분만 반송 | 대량 생성에 품질 게이트 |
| **Plan-Execute + reflect** | 계획·실행 + 실패 교훈 누적 | 긴 마이그레이션의 반복 실행 |
| **fan-out + grade-revise + reflect** | 병렬 + 채점 + 교훈 | V9 표준 대형 루프(`루프_카탈로그.md` ⑧) |

## 패턴 → 루프 유형 → 카탈로그 매핑
| 패턴 | 루프 유형(§6) | 카탈로그 예 |
|---|---|---|
| ReAct | 인터랙티브 | ① PR-그린(소규모) |
| Plan-and-Execute | 백그라운드 자율 | ④ 야간 리팩토링/의존성 |
| Evaluator-Optimizer | grade-revise | ② 커버리지 상향 |
| Reflexion | grade-revise + 메모리 | ⑦ Reflexion 학습 루프 |
| fan-out | fan-out | ⑧ 멀티에이전트 오케스트레이션 |
