# 하네스 엔지니어링 가이드 (V9 신규)

> 루프는 더 큰 **에이전트 하네스(harness, AI 제어판)** 의 일부다. 하네스 엔지니어링은 "모델 주변의 환경을 설계해 모델을 신뢰 가능한 자율 에이전트로 만드는" 2026년 핵심 분야다.[^1][^2]
> 이 문서는 V9의 기존 자산(V7·V8 계승)을 **하네스 5계층**으로 배치해, 루프가 어디에 끼워지는지 한눈에 보여준다.

## 왜 하네스인가
좋은 루프 하나만으로는 부족하다. 도구가 빈약하거나, 세션 간 기억이 없거나, 가드레일·관찰성이 없으면 자율 루프는 무너진다. 성숙도 단계: **프롬프트 → 컨텍스트 → 하네스 엔지니어링**(`루프엔지니어링_방법론.md` §2). V9은 루프를 하네스 안에 정식 배치한다.

## 하네스 5계층 ↔ V9 자산 매핑
| 계층 | 역할 | V9 자산(계승+신규) |
|---|---|---|
| **1. 도구 오케스트레이션** | 에이전트가 쓸 도구·서브에이전트·라우팅 | MCP 공유DB 도구, `model-router`/`route_model`, `loop-orchestrator`(fan-out), Claude Code+Codex 이중 |
| **2. 검증 루프** | 결과를 밀어내는 피드백(테스트·타입·리뷰·채점) | 훅(typecheck·eval-gate), `loop-grader`(grade-revise), eval 골든 케이스, `/goal` 평가 |
| **3. 컨텍스트 & 메모리** | 무엇을 보여주고 무엇을 기억할지 | 하이브리드 검색(pgvector), `loop-context-compact.sh`(CONTEXT), `loop_lessons`+`loop-reflector`(REFLECT), 공유DB |
| **4. 가드레일** | 안전·권한·예산·정지 | RBAC, PII 스캔, `loop-budget-guard`/`loop-budget-cap.sh`, `loop-tick-stop-check.sh`, `loop-no-progress-check.sh`, `human_gate` |
| **5. 관찰성** | 무슨 일이 일어났나 추적 | OTel·Prometheus·Grafana, `loop_runs`, `loop-report-emit.sh`, audit_log |

> 핵심: **루프는 2계층(검증)을 심장으로, 3·4계층(메모리·가드레일)에 의해 안전해지고, 1·5계층(도구·관찰성) 위에서 돈다.**

## 계층별 설계 점검
### 1) 도구 오케스트레이션
- 도구는 적고 명확하게(과도한 도구는 선택 마비). 원시 출력은 컨텍스트에 직접 붓지 말고 요약/샌드박스.[^2]
- fan-out은 리드만, 깊이=1, 동시성 상한.

### 2) 검증 루프
- "밀어낼 것이 없는 루프는 자기 자신과 동의하는 루프"다 — 테스트·타입체크·리뷰·grader 중 최소 하나의 **객관 신호**를 둔다.[^3]
- 완료 판정은 LLM이 아니라 명령 결과/hook/grader가 한다(false done 방지).

### 3) 컨텍스트 & 메모리
- **컨텍스트 위생**: 매 tick 압축·외부화·선별 주입(`loop-context-compact.sh`).
- **에피소드 메모리**: 실패 교훈을 `loop_lessons`에 적고 재주입(`loop-reflector`).
- 세션 간 상태는 컨텍스트가 아니라 공유DB/변수에 영속화.

### 4) 가드레일
- BUDGET(tick·누적), STOP(결정적 OR), 무진행 감지, RBAC·PII, 비가역 행동 `human_gate`.
- **자율 전에 통제**: 사다리(`루프엔지니어링_방법론.md` §9)를 한 칸씩 올린다.

### 5) 관찰성
- 모든 루프는 종료 시 `loop_runs` 1건 + REPORT. 회귀·비용·정지사유를 대시보드로.
- 사후 `loop-postmortem`이 기록을 분석해 루프·eval을 개선.

## 30분 적용 레시피
1. 대상 리포에 V9 드롭인(`사용방법/install-to-project.sh`) → 5계층 자산 배치.
2. 검증 신호 1개 확정(테스트/CI) → 2계층 확보.
3. 카탈로그에서 루프 1종 선택 → 6요소 + 3규율 채움.
4. 가드레일(BUDGET/STOP/무진행/`human_gate`) 확인 → 4계층 확보.
5. env:dev dry-run → `loop_runs`·REPORT로 5계층 확인 → 자율 사다리 한 칸 상승.
