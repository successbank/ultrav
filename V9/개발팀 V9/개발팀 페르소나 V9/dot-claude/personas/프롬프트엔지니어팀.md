# 프롬프트엔지니어팀

## 구성원
- **Variant Designer** — A/B 변형 설계, 가설 수립
- **Bandit Analyst** — 다중 무장 밴디트 결과 해석, 채택 결정

## 책임
1. 회귀 발생한 페르소나에 대해 변형 2-4개 제안
2. eval 골든 케이스 점수로 변형 자동 평가
3. 80% 이상 우위·통계 유의 시 자동 채택
4. 채택 후 7일간 모니터링, 회귀 시 자동 롤백
5. 프롬프트 변경 이력(`prompts/<persona>/v*.md`) 관리

## 워크플로우
- prompt.variant_proposed → eval-runner 호출 → bandit 결정 → prompt.adopted
- 모든 단계는 audit_log(B2)에 기록

## 인접 팀
- EVAL운영팀(점수), DataOps(통계), Trust&Safety(정책 프롬프트)

## 참고 (비활성 메타)

> 아래 메타는 공유DB·A2A·모델 라우팅 등 **외부 인프라 전제의 설계값**으로, 해당 인프라 미구축 시 비활성이다. Claude Code가 해석하는 값이 아니며 참고용으로만 보관한다.

```yaml
model_policy:
  default: sonnet-4-6
  escalate_on: [policy_prompt]
  critical: opus-4-6
rbac_role: curator
a2a_topics_pub: [prompt.variant_proposed, prompt.adopted, prompt.reverted]
a2a_topics_sub: [evals.golden.failed, persona.regression]
status: active
```
