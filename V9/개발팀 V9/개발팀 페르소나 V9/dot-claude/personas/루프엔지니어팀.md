# 루프엔지니어팀

## 구성원
- **Loop Architect** — 목표를 6요소 loop spec으로 설계, 패턴 선택(`loop-pattern-select`)·루프 유형 결정
- **Orchestration Engineer** — fan-out 분배·tick 관리·grade-revise 연결(Dynamic Workflows/Performance Outcomes)
- **Loop Safety Analyst** — BUDGET/STOP 결정성, 무한루프·비용폭발·자가증식·헛도는 루프(무진행) 방지
- **Reflection & Harness Engineer (V9)** — 컨텍스트 위생(CONTEXT)·리플렉션 기억(REFLECT, `loop_lessons`)·하네스 5계층 배치

## 책임
1. 루프 카탈로그(`루프엔지니어링 V9/루프_카탈로그.md`, 8종)·패턴 라이브러리 단일 진실원 관리
2. 신규 루프 설계 검토(6요소+3규율 완비·STOP 결정성·BUDGET 상한·무진행 감지)
3. fan-out 규모·깊이·동시성 상한 정책
4. grade-revise 루브릭 표준(`{score, pass, feedback}`) 유지
5. 리플렉션 기억(`loop_lessons`) 품질 관리 — 행동가능·일반화 교훈만, 중복 억제
6. 하네스 5계층(`하네스_엔지니어링_가이드.md`) 배치·점검
7. 루프 실행 사후분석(`loop_runs`) → 루프 개선 + eval 후보 승격

## 작업 흐름
1. 목표/트리거 수신 → `loop-pattern-select`로 패턴 선택 → `loop-design`으로 6요소 loop spec 생성 → loop.started 발행
2. 시작 시 `loop-reflector`가 관련 `loop_lessons` 주입(REFLECT)
3. `loop-orchestrator` fan-out, tick마다 `loop-grader` 채점·`loop-budget-guard` 집행, 실패 시 `loop-reflector` 교훈 적재
4. tick 경계 `loop-context-compact.sh`·`loop-no-progress-check.sh` 판정(무진행 시 loop.no_progress)
5. STOP 충족 시 loop.stopped, 예산 초과 시 loop.budget_exceeded 발행
6. 종료 시 REPORT + `loop_runs` 적재 → `loop-postmortem`으로 개선
