# 최신 트렌드 웹리서치 보고서 — V9 설계 근거

> 작성일: 2026-06-27
> 목적: V7→V9 업그레이드(루프 엔지니어링 정식화 + 안드로이드 네이티브 트랙)의 외부 근거를 정리하고, 각 트렌드가 V9의 어떤 자산으로 반영됐는지 추적 가능하게 매핑한다.
> 입장: 이 문서는 V9 홍보가 아니라 검증용이다. 트렌드를 인용하되, 트렌드가 곧 정당성은 아니라는 점을 ⑥에서 따로 짚는다.

---

## ① 요약 (3줄)

- 2026년 에이전틱 코딩의 핵심 레버리지는 "좋은 프롬프트 한 번(one-shot)"에서 **"좋은 루프를 설계하는 것(loop engineering)"**으로 이동했다. 사람은 더 이상 매 턴 프롬프트하지 않고, 에이전트를 굴리는 루프를 설계한다.
- Claude Code 2026은 이 변화를 네이티브로 지원한다: subagents(독립 컨텍스트/도구권한), Dynamic Workflows(서브에이전트 fan-out), Performance Outcomes(grader가 루브릭 미달 시 재작업 지시), `/goal`(완료조건까지 자율 반복), hooks(결정적), skills(점진적 공개).
- 동시에 안드로이드는 Compose-first + 온디바이스 AI(Gemini Nano 4) + AppFunctions(앱=온디바이스 MCP) + 안정화된 Android CLI로, 에이전트가 직접 빌드/실기기 실행하는 단계에 진입했다. V9은 이 두 흐름을 각각 "루프 엔지니어링"과 "안드로이드 네이티브 트랙"으로 흡수했다.

## ② 루프 엔지니어링이란 무엇이고, 왜 지금인가

**정의.** 루프 엔지니어링은 AI 코딩 에이전트의 피드백 루프(계획 → 코드 변경 → 결과 관찰 → 수정)를 **설계·운영·개선하는 방법론**이다. 핵심 슬로건은 "에이전트에게 프롬프트하지 말고, 에이전트를 프롬프트하는 루프를 설계하라"이다. 이 표현은 Google의 Addy Osmani가 대중화했고, Peter Steinberger("you should be designing loops that prompt your agents")와 Anthropic Claude Code 리드 Boris Cherny("내 일은 이제 모델에 프롬프트하는 게 아니라 루프를 쓰는 것")가 같은 취지로 언급했다. ([mindstudio.ai](https://www.mindstudio.ai/blog/what-is-loop-engineering-ai-coding-agents), [the-ai-corner.com](https://www.the-ai-corner.com/p/loop-engineering-coding-agents-2026))

**계보(ReAct → 루프 엔지니어링).** 2022년의 ReAct(Reason+Act: 사고와 행동을 교차)가 단일 에이전트의 추론-행동 루프를 열었다면, 2026년의 루프 엔지니어링은 그 루프를 **다중 에이전트·예산·완료조건과 함께 명시적으로 엔지니어링**하는 단계다. 품질 차이는 베이스 모델이 아니라 루프 설계에서 난다는 것이 공통된 관찰이다. ([datasciencedojo.com — Agentic Loops: From ReAct to Loop Engineering 2026](https://datasciencedojo.com), [explainx.ai](https://explainx.ai/blog/loop-engineering-coding-agents-claude-code-guide-2026))

**핵심 구조: DOER와 CHECKER.** 모든 루프에는 무언가를 만드는 DOER와 그것이 충분한지 판정하는 CHECKER가 있다. 업계 합의는 "AI(DOER)는 어려운 부분이 아니었다 — 어려운 건 CHECKER다"이다. 즉 루프의 품질은 **판정자(grader)의 품질**에 달려 있다. ([mindstudio.ai](https://www.mindstudio.ai/blog/what-is-loop-engineering-ai-coding-agents))

**왜 지금인가.** one-shot 프롬프팅은 컨텍스트가 커지고 작업이 다단계가 될수록 한계가 분명해졌다. 모델은 충분히 좋아졌고, 남은 병목은 "언제 멈추고, 무엇을 합격으로 볼지"를 사람이 설계하는 일이다. ([kilo.ai — What is Loop Engineering](https://kilo.ai/articles/what-is-loop-engineering), [resources.anthropic.com — 2026 Agentic Coding Trends Report](https://resources.anthropic.com/2026-agentic-coding-trends-report))

**6요소 해부도 (V9 정식 채택).** V9은 루프를 6개 슬롯으로 분해해 설계·검수한다:

| 요소 | 질문 | 빠지면 생기는 사고 |
|---|---|---|
| **TRIGGER** | 무엇이 루프를 시작시키는가 | 의도치 않은 시점/빈도로 작동 |
| **SCOPE** | 어떤 파일·디렉터리·작업에만 손대는가 | 무관한 코드까지 변경(폭주) |
| **ACTION** | 매 틱(tick)마다 무엇을 하는가 | 행동이 모호 → 헛돌기 |
| **BUDGET** | 토큰/시간/틱/비용 상한 | **비용 폭발·무한루프** |
| **STOP** | 어떤 조건에서 멈추는가(완료/포기) | 거짓 완료 또는 영원히 안 멈춤 |
| **REPORT** | 무엇을, 어디에 기록하는가 | 은밀한 실패·감사 불가 |

이 6요소는 V9의 `루프엔지니어링_방법론.md`에 "해부도"로, `루프_설계_체크리스트.md`에 점검표로 들어가 있고, BUDGET/STOP은 뒤(④, ⑥)에서 자율성 안전장치의 핵심으로 다시 다룬다.

## ③ 에이전틱 코딩 2026 트렌드

### (1) 완료조건(Completion conditions)이 일급 시민이 됐다
Claude Code는 v2.1.139(2026-05-11)에서 `/goal`을 추가했다 — 사용자가 작성한 조건이 참이 될 때까지 **턴을 넘어 자율 반복**하는 네이티브 루프이며, 별도의 빠른 모델이 결과를 채점한다. goal 루프는 "결과(outcome)를 정하고, 검증되거나 막힐 때까지 에이전트를 돌리는" 가장 강력하면서도 가장 자주 잘못 쓰이는 루프 유형으로 평가된다. ([the-ai-corner.com](https://www.the-ai-corner.com/p/loop-engineering-coding-agents-2026), [explainx.ai](https://explainx.ai/blog/loop-engineering-coding-agents-claude-code-guide-2026))
→ V9 반영: `완료조건_가이드.md`(STOP/Completion 심화 + 거짓 완료 방지).

### (2) 컨텍스트 엔지니어링 > 프롬프트 엔지니어링
에이전트에게 "무엇을 보게 할지(파일/도구/지식)"를 설계하는 것이 한 줄 프롬프트보다 결정적이다. skills의 점진적 공개(progressive disclosure)와 subagent의 독립 컨텍스트가 이 흐름의 도구다. ([resources.anthropic.com](https://resources.anthropic.com/2026-agentic-coding-trends-report), [claude.com/blog](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more))

### (3) 하이브리드 워크플로우: IDE 계획 → 샌드박스 실행 → CI/PR 리뷰
실무 권장 형태는 단일 거대 자율 루프가 아니라 **3단 하이브리드**다: (a) IDE에서 사람이 계획·범위 합의 → (b) 격리 샌드박스/백그라운드 fork에서 에이전트가 실행 → (c) 변경은 CI 게이트와 PR 리뷰를 통과해야 머지. 자율성과 통제를 동시에 얻는 구조다. ([developersdigest.tech — Loop Engineering Definitive Guide](https://www.developersdigest.tech/blog/loop-engineering-definitive-guide), [resources.anthropic.com](https://resources.anthropic.com/2026-agentic-coding-trends-report))
→ V9 반영: 루프 카탈로그의 "PR-그린 루프", `pre-pr-eval-gate.sh` 훅, 크로스플랫폼 CI.

## ④ Claude Code 2026 네이티브 기능 정리

| 기능 | 무엇인가 | V9에서의 의미 |
|---|---|---|
| **Subagents** | 독립 컨텍스트 + 도구 권한을 가진 하위 에이전트 | 28팀 페르소나/전용 에이전트를 격리 실행 |
| **Dynamic Workflows** | 다수 서브에이전트 fan-out(병렬) | 루프 orchestrator가 작업 분기·병합 |
| **Performance Outcomes** | grader가 루브릭 미달 시 재작업(revise) 지시 | grade-revise 루프(loop-grader) |
| **Completion conditions / `/goal`** | 조건 충족까지 자율 반복(v2.1.139) | STOP/완료조건 설계의 네이티브 기반 |
| **Hooks** | 결정적·환각 불가한 이벤트 훅 | BUDGET/STOP/REPORT를 코드로 강제 |
| **Skills** | 점진적 공개되는 절차 지식 | loop/android 스킬로 절차 표준화 |
| **백그라운드 fork** | 격리된 백그라운드 실행 | 샌드박스 실행 단계 담당 |

출처: [claude.com/blog — Steering Claude Code](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more), [code.claude.com/docs — Sub-agents](https://code.claude.com/docs/en/sub-agents), [explainx.ai — steering Claude Code 2026](https://explainx.ai/blog/loop-engineering-coding-agents-claude-code-guide-2026).

**검증 메모:** hooks가 "결정적·환각 불가"라는 점이 V9 안전 설계의 핵심 가정이다. 즉 BUDGET 상한과 STOP 체크를 LLM 판단이 아니라 훅 스크립트로 강제할 수 있어야, ⑥의 비용·무한루프 위험이 실제로 막힌다. 이 가정이 깨지면(훅이 우회되면) V9의 안전 주장도 약해진다 — 비평 문서에서 별도로 추궁한다.

## ⑤ 안드로이드 네이티브 + 온디바이스 AI 동향

- **Compose-first가 표준.** Google AI Studio가 Kotlin+Jetpack Compose 네이티브 앱을 생성하는 단계가 됐다. 뷰 기반 레거시보다 Compose가 신규 개발의 기본값이다. ([android-developers.googleblog.com — 2026-05 I/O](https://android-developers.googleblog.com), [ai.google.dev — AI Studio Android](https://ai.google.dev/gemini-api/docs/aistudio-android))
- **온디바이스 AI: Gemini Nano 4.** 기기 내에서 추론하는 소형 모델로, 네트워크 없이 프라이버시 보존 추론이 가능. ([developer.android.com/studio/gemini](https://developer.android.com/studio/gemini))
- **AppFunctions = 온디바이스 MCP.** 앱이 자신의 기능을 온디바이스 MCP 서버처럼 노출 → 에이전트가 기기 내 앱 기능을 도구로 호출. ([android-developers.googleblog.com](https://android-developers.googleblog.com))
- **안정화된 Android CLI.** 에이전트가 CLI로 빌드/실기기 실행을 직접 수행하는 루프가 가능해짐(루프의 ACTION/관찰 단계가 실기기까지 닿음).

→ V9 반영: Android_Native팀·OnDevice_AI팀 페르소나, `android-native-builder` 에이전트, android 빌드/릴리스 훅, android 스킬 4종(`android-compose-screen`/`android-gradle-module`/`android-appfunctions-mcp`/`android-release-play`), platform eval 2종, `안드로이드_네이티브_가이드`. RN은 폐기하지 않고 **병행**(트레이드오프는 ⑥·비평 문서 참조).
