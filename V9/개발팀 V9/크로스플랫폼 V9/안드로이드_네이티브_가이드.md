# 안드로이드 네이티브 트랙 가이드 (V9)

> Google I/O '26 기준. 기존 RN(Mobile Platform팀) 트랙은 그대로 두고, Kotlin/Compose 네이티브 전담 트랙을 **병행 추가**한다.

## 1. 왜 네이티브 트랙을 추가했나 (RN 병행 이유)
RN은 다수 화면을 iOS·Android 공유 코드로 빠르게 출하하기에 여전히 유효하다. 그러나 다음 영역에서 네이티브가 명확히 우월하다.

| 동인 | 네이티브가 필요한 이유 |
|---|---|
| 플랫폼 표준 | 구글이 모든 신규 가이드·라이브러리를 **Compose-first**로 전환. 신규 UI는 Compose + Kotlin이 기본선 |
| 하드웨어 | Camera·GPS·Accelerometer·Bluetooth(BLE) 등 **하드웨어 최적 접근**, 지연·전력·생명주기 제어 |
| 온디바이스 AI | **Gemini Nano 4**(온디바이스 추론)와 **AppFunctions**(앱=온디바이스 MCP 서버)는 네이티브 진입점 |
| AI 주도 개발 | Google AI Studio + Antigravity Agent가 **완전한 Kotlin+Compose 프로젝트**를 자연어로 생성, **Android CLI**로 에이전트가 빌드·실기기 실행 |

→ 결론: 공유·범용 UI는 RN, **하드웨어·온디바이스 AI·고성능·플랫폼 표준 UI는 네이티브**. 두 트랙을 자산(페르소나·에이전트·스킬·훅·eval)까지 분리해 병행한다.

## 2. 스택 결정
| 분야 | 선택 | 근거 |
|---|---|---|
| 언어 | Kotlin | 구글 1순위 언어, 코루틴·널 안전성 |
| UI | **Jetpack Compose (Compose-first)** | 구글 표준, 선언형, Preview·테스트 용이 |
| 공유 로직 | Kotlin Multiplatform(KMP) *선택적* | 비즈니스/데이터 계층을 iOS·RN과 재사용 검토(아래 기준) |
| DI | Hilt | 표준 DI, 테스트 대체 용이 |
| 로컬 DB | Room | SQLite 추상화, Flow 연동, 마이그레이션 |
| 비동기 | Coroutines / Flow | 구조적 동시성, UiState 스트림 |
| 빌드 | Gradle + 버전 카탈로그 + convention plugin | 모듈 간 설정 일관성, 버전 단일 출처 |

### KMP 채택 기준
- **채택**: 순수 비즈니스 규칙·검증·DTO·네트워크/저장 계약처럼 UI 비의존 로직이 다수이고 iOS/RN과 재사용 가치가 큼.
- **보류**: UI 밀착 로직, 플랫폼 SDK 직접 의존, 팀 KMP 숙련도 낮음, 검증 비용이 재사용 이득보다 큼.

## 3. 프로젝트 구조 (모듈)
```
android/
  app/                      # 진입점, DI 그래프, 네비게이션 호스트
  feature/
    feature-home/           # 화면 단위 (Compose + ViewModel + UiState)
    feature-profile/
  core/
    core-ui/                # 디자인 시스템, 공통 Composable, 테마
    core-data/              # Repository, Room, 네트워크
    core-domain/            # UseCase, 도메인 모델 (UI 비의존)
    core-common/            # 유틸, 결과 타입
  build-logic/              # convention plugin (android-library/kotlin/compose 공통)
  gradle/libs.versions.toml # 버전 카탈로그 (단일 출처)
```
- 의존 방향: `feature → core-domain → core-data` 단방향, **순환 의존 금지**.
- KMP 적용 시 `core-domain`/`core-common`을 `:shared`(KMP)로 승격해 iOS·RN과 공유.

## 4. 온디바이스 AI (Gemini Nano 4 + AppFunctions)
- **Gemini Nano 4**(프리뷰): 데이터 추출·요약 등 **온디바이스 추론**. 민감정보는 단말에서 처리해 데이터 단말 이탈 최소화.
- **AppFunctions**: 앱이 **온디바이스 MCP 서버**처럼 동작 — 앱의 도구·서비스·데이터를 시스템과 에이전트에 공유. AI 주도 개발·에이전트 시대의 핵심 진입점.
- **추론 라우팅**: 민감도·지연·기기 성능 기준으로 온디바이스 우선, 불가 시 동의 전제 클라우드 폴백. Nano 미탑재 기기는 안전한 대체 경로.
- 담당: **OnDevice AI팀** (스킬 `android-appfunctions-mcp`).

## 5. AI 주도 개발 워크플로우
1. **생성**: Google AI Studio + Antigravity Agent가 자연어 프롬프트로 Kotlin+Compose 프로젝트 골격 생성 (Android Studio는 iOS 앱 포팅 기능 추가).
2. **빌드·실행**: 안정화된 **Android CLI**로 AI 에이전트가 Android Studio 기능(SDK 다운로드, 실기기 앱 실행)에 직접 접근.
3. **자율 반복**: `android-native-builder` 에이전트가 영향 모듈 산정 → 변경 → `./gradlew :app:assembleDebug lintDebug test` → Maestro 스모크 → 실패 시 **루프엔지니어링 loop**(loop-run)과 연계해 **빌드-그린까지 자율 반복**.
4. **게이트**: 모든 PR은 `pre-android-build.sh`(wrapper·ktlint/detekt·lintDebug) 통과 + `./gradlew test lintDebug`.
> 주의: **서명·실기기 실행은 로컬 전용**. Codex 원격 미러는 빌드·lint·단위 테스트까지만 수행(에이전트 .codex 미러 주석 참조).

## 6. 테스트
| 계층 | 도구 | 비고 |
|---|---|---|
| 단위 | JUnit + Coroutines Test + Turbine(Flow) | 도메인·ViewModel |
| Compose UI | createComposeRule + semantics | 상태·접근성 assertion |
| E2E | **Maestro** + **UiAutomator** | 핵심 플로우·시스템 상호작용 |
| 성능 | **Baseline Profiles** + Macrobenchmark | 콜드 스타트·스크롤 개선 |
| 접근성 | TalkBack·터치타깃 48dp·대비 | 출시 게이트 |

## 7. 릴리스
- **AAB** 빌드 + **Play App Signing**(업로드 키 서명).
- 트랙 승급: **internal → closed → open → production**.
- **단계적 출시(staged rollout)**: rollout% 1%→10%→50%→100%, 크래시·ANR 임계 초과 시 중단/롤백.
- 사전 등록(pre-registration) 옵션. 게이트: `pre-android-release.sh`(서명 환경변수·targetSDK·권한 최소화·개인정보처리방침).
- 담당: **Android Native팀** (스킬 `android-release-play`).

## 8. 보안 / 프라이버시
- 토큰은 **Keystore**, 디스크 OS 암호화 전제 (플랫폼별 보안 매트릭스 참조).
- **권한 최소화**: 위험 권한(SMS·전체 패키지 조회·외부 저장소 전체)은 정당성·선언 양식 필수, 미사용 권한 제거.
- **온디바이스 우선**: 민감정보 요약·추출은 Gemini Nano로 단말 처리, 데이터 단말 이탈 최소화. 클라우드 전송은 동의 전제.
- 개인정보처리방침 링크 Play 콘솔·앱 내 노출.

## 9. RN(크로스플랫폼)과의 경계·선택 기준
| 기준 | RN (Mobile Platform팀) | 네이티브 (Android Native팀) |
|---|---|---|
| 주 용도 | iOS·Android 공유 범용 UI, 빠른 출하 | 안드로이드 표준 UI, 하드웨어·온디바이스 AI |
| 하드웨어 | 브리지/모듈로 접근(제약 가능) | Camera/GPS/BLE 등 **최적 접근** |
| 온디바이스 AI | 제한적 | **Gemini Nano + AppFunctions** 네이티브 |
| 성능 | 일반 화면 충분 | 고프레임·복잡 애니메이션·저지연 우월 |
| UI 표준 | RN 컴포넌트 | **Compose-first** 구글 표준 |
| 코드 공유 | TS 생태 공유 | KMP로 도메인 계층 선택 공유 |
| 선택 규칙 | 화면이 단순·공유가치 큼 → RN | 하드웨어/온디바이스AI/고성능/플랫폼표준 → 네이티브 |

경계 원칙: 한 화면을 두 트랙으로 중복 구현하지 않는다. 신규 기능은 위 기준으로 트랙을 먼저 확정하고, 도메인 로직은 가능하면 KMP로 공유한다.

## 10. 관찰성 / A2A 연계
- 빌드 실패 시 `android-native-builder`가 원인 요약과 함께 `android.build_failed` 토픽 발행 → 루프엔지니어링 loop가 수신해 재시도/에스컬레이션.
- 릴리스 완료 시 `android.released` 발행 → OnDevice AI팀이 `ondevice.inference_ready` 갱신 판단에 활용.
- 런타임 에러는 `errors.platform.android`로 수집 → Android Native팀 구독. 크래시·ANR 임계 초과 시 Play 단계적 출시 자동 중단 권고.
- 모델 호출은 `model_policy`(default sonnet-4-6, native_api/gradle_graph/play_policy 시 escalate)로 라우팅, 비용은 usage_tracking에 적재.

## 11. AI 주도 개발 — 시작 프롬프트 예시
Google AI Studio + Antigravity Agent에 줄 자연어 프롬프트 예:
```
Kotlin + Jetpack Compose로 안드로이드 앱을 생성하라.
- 모듈: app / feature-home / core-ui / core-domain / core-data
- DI: Hilt, 로컬: Room, 비동기: Coroutines/Flow
- 홈 화면: 목록 + 로딩/에러/빈 상태, 상태 호이스팅, UiState(sealed)
- 빌드 검증: ./gradlew :app:assembleDebug lintDebug test 통과까지 반복
- 버전 카탈로그(libs.versions.toml) 사용, convention plugin 적용
```
생성 후 Android CLI로 에이전트가 SDK 다운로드·실기기 실행을 수행하고, `android-native-builder`가 그린까지 자율 반복한다.

## 12. 코드 공유·공존 운영
- **공유 후보**: 도메인 규칙·검증·DTO·동기화 계약. KMP `:shared`로 올려 RN(브리지)·iOS와 재사용.
- **공존 규칙**: RN 앱과 네이티브 앱이 같은 백엔드·동기화 엔진(공유DB 인프라)을 사용하되, 화면 소유권은 트랙별 단일.
- **점진 도입**: 기존 RN 화면을 네이티브로 옮길 때는 기능 플래그로 신·구 경로를 병행 후 단계적 전환(빅뱅 금지).
- **자산 관리**: 네이티브 전담 자산(페르소나·에이전트·스킬·훅·eval)은 본 트랙에만 추가하고 공유 파일(README/INDEX/settings)은 수정하지 않는다.
