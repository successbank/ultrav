# 제품 리뷰 시스템 테스트 시나리오 및 페르소나

## 테스트 페르소나

### 페르소나 1: 김민지 (만족한 고객)
- **나이**: 28세
- **직업**: IT 기업 직장인
- **특성**: 온라인 쇼핑을 자주 하며, 구매 후 항상 리뷰를 작성하는 성실한 고객
- **목표**: 만족한 제품에 대해 상세한 리뷰를 작성하여 다른 고객들에게 도움을 주고 싶음
- **기대**: 별점 5점, 긍정적인 텍스트 리뷰 작성

### 페르소나 2: 박준호 (불만족 고객)
- **나이**: 35세
- **직업**: 자영업자
- **특성**: 꼼꼼한 성격으로 제품에 문제가 있으면 반드시 피드백을 남김
- **목표**: 제품의 문제점을 명확히 지적하여 개선을 요청
- **기대**: 별점 2점, 구체적인 불만 사항 작성

### 페르소나 3: 이수진 (신중한 구매자)
- **나이**: 42세
- **직업**: 주부
- **특성**: 구매 전 리뷰를 꼼꼼히 읽고, 필터링/정렬 기능을 적극 활용
- **목표**: 다른 고객들의 리뷰를 통해 신뢰할 수 있는 정보 수집
- **기대**: 리뷰 목록을 별점순, 최신순으로 정렬하여 탐색

### 페르소나 4: 최동욱 (악의적 사용자)
- **나이**: 24세
- **직업**: 대학생
- **특성**: 시스템의 허점을 찾아내려는 호기심 많은 사용자
- **목표**: 구매하지 않은 제품에 리뷰 작성, 중복 리뷰 시도 등 보안 테스트
- **기대**: 시스템이 적절히 차단해야 함

### 페르소나 5: 김태희 (미로그인 방문자)
- **나이**: 31세
- **직업**: 디자이너
- **특성**: 제품을 둘러보다가 리뷰를 읽고 싶어하는 비회원
- **목표**: 로그인 없이 리뷰를 읽고, 필요시 로그인하여 구매
- **기대**: 리뷰 조회는 가능하되, 작성은 로그인 필요

## 테스트 시나리오

### 시나리오 1: 행복 경로 (Happy Path) - 리뷰 작성 및 조회

**페르소나**: 김민지 (만족한 고객)

**사전 조건**:
- 김민지는 이미 제품을 구매하고 배송을 받았음 (주문 상태: DELIVERED)
- test@ultra.com 계정으로 로그인됨

**테스트 단계**:
1. 제품 상세 페이지 접속
2. "고객 리뷰" 섹션으로 스크롤
3. 리뷰 작성 폼 확인
4. 별점 5점 선택
5. 리뷰 텍스트 입력: "제품이 기대 이상으로 훌륭합니다. 배송도 빠르고 포장 상태도 완벽했어요. 다른 분들께도 강력 추천합니다!"
6. "리뷰 등록" 버튼 클릭
7. 성공 메시지 확인
8. 리뷰 목록에 새 리뷰가 표시되는지 확인

**예상 결과**:
- ✅ 리뷰가 성공적으로 등록됨
- ✅ 리뷰 목록 최상단에 방금 작성한 리뷰가 표시됨
- ✅ 구매 인증 뱃지가 표시됨
- ✅ 평균 별점이 업데이트됨

---

### 시나리오 2: 부정적 리뷰 작성

**페르소나**: 박준호 (불만족 고객)

**사전 조건**:
- 박준호는 제품을 구매했지만 만족하지 못함
- 새로운 테스트 계정으로 로그인됨

**테스트 단계**:
1. 제품 상세 페이지 접속
2. 리뷰 작성 폼 열기
3. 별점 2점 선택
4. 부정적 리뷰 작성: "제품 사진과 실물이 많이 다릅니다. 색상이 예상과 달라서 실망했어요."
5. 리뷰 등록

**예상 결과**:
- ✅ 부정적 리뷰도 정상적으로 등록됨
- ✅ 낮은 별점이 정확히 표시됨
- ✅ 평균 별점이 재계산되어 감소함

---

### 시나리오 3: 리뷰 필터링 및 정렬

**페르소나**: 이수진 (신중한 구매자)

**사전 조건**:
- 제품에 다양한 별점의 리뷰가 5개 이상 존재

**테스트 단계**:
1. 제품 페이지 접속
2. 리뷰 섹션에서 정렬 옵션을 "평점 낮은순"으로 변경
3. 낮은 별점 리뷰가 먼저 표시되는지 확인
4. 별점 필터를 "⭐⭐⭐⭐⭐ (5점)"으로 설정
5. 5점 리뷰만 표시되는지 확인
6. 리뷰가 5개 이상일 경우 "더보기" 버튼 클릭
7. 추가 리뷰가 로드되는지 확인

**예상 결과**:
- ✅ 정렬 기능이 정확히 작동함
- ✅ 필터링이 정확히 작동함
- ✅ 페이지네이션이 정상 작동함

### 시나리오 4: 보안 테스트 - 구매 검증

**페르소나**: 최동욱 (악의적 사용자)

**사전 조건**:

2. 리뷰 작성 폼에서 별점 1점 선택
3. 악의적인 리뷰 작성 시도: "이 제품은 최악입니다!"
4. "리뷰 등록" 버튼 클릭

**예상 결과**:
- ✅ 에러 메시지 표시: "구매한 제품에 대해서만 리뷰를 작성할 수 있습니다"
- ✅ 리뷰가 데이터베이스에 저장되지 않음
- ✅ HTTP 403 Forbidden 응답

### 시나리오 5: 중복 리뷰 방지

**예상 결과**:

- ✅ HTTP 400 Bad Request 응답

## 엣지 케이스 테스트

### EC-1: 리뷰가 0개일 때
- 리뷰 목록에 "아직 리뷰가 없습니다" 메시지 표시
- 평균 별점이 표시되지 않음

### EC-2: 리뷰가 정확히 5개일 때
- "더보기" 버튼이 표시되지 않음

### EC-3: 리뷰가 6개 이상일 때
- 초기 5개만 표시
- "더보기" 버튼이 표시됨
- 클릭 시 5개씩 추가 로드

### EC-4: 특수문자 포함 리뷰
- HTML 태그: `<script>alert('XSS')</script>`
- SQL Injection: `'; DROP TABLE reviews; --`
- 예상 결과: 모두 안전하게 이스케이프되어 표시됨

### EC-5: 매우 긴 텍스트 리뷰
- 10,000자 이상의 긴 리뷰 작성
- 예상 결과: 정상적으로 저장되고 표시됨 (데이터베이스 @db.Text 타입)
