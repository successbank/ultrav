# Ultra 쇼핑몰 관리자 페이지 개발 PRD (Product Requirements Document)

## 프로젝트 개요
Ultra 쇼핑몰의 관리자 전용 대시보드 및 관리 페이지를 구축하여 상품, 주문, 사용자, 카테고리를 효율적으로 관리할 수 있는 시스템을 개발합니다.

## 기술 스택
- Next.js 14.2.5 (App Router)
- TypeScript
- Prisma ORM (PostgreSQL)
- NextAuth.js v5 (인증/권한)
- Tailwind CSS + Radix UI
- React Hook Form + Zod (폼 검증)

## 핵심 요구사항

### 1. 인증 및 권한 관리 (Authentication & Authorization)
**목표**: 관리자만 접근 가능한 보안된 관리 시스템 구축

**세부 요구사항**:
- NextAuth.js를 사용한 인증 시스템 구현
- UserRole enum (USER, ADMIN) 기반 역할 기반 접근 제어(RBAC)
- 미들웨어를 통한 /admin/* 라우트 보호
- 관리자 로그인 페이지 (/admin/login)
- 세션 기반 인증 및 토큰 관리
- 비인가 접근 시 자동 리다이렉션

**보안 고려사항**:
- 서버 컴포넌트에서 권한 검증
- Server Action에서 이중 권한 체크
- 클라이언트 측 UI 가드는 UX용, 서버 측이 실제 보안 담당

### 2. 관리자 대시보드 (Admin Dashboard)
**경로**: `/admin/dashboard`

**주요 기능**:
- 전체 주문 통계 (총 주문 수, 금일 주문, 주문 상태별 분포)
- 매출 통계 (일간/주간/월간 매출, 전년 대비 성장률)
- 상품 통계 (총 상품 수, 재고 부족 상품, 카테고리별 분포)
- 사용자 통계 (총 회원 수, 신규 가입자, 활성 사용자)
- 최근 주문 목록 (최신 10건)
- 인기 상품 TOP 5
- 빠른 액션 버튼 (상품 추가, 주문 관리 등)

**데이터 소스**:
- Prisma 집계 쿼리 활용
- Redis 캐싱으로 성능 최적화
- 실시간 업데이트는 폴링 또는 웹소켓 고려

### 3. 상품 관리 (Product Management)
**경로**: `/admin/products`

**기능 목록**:
3.1 상품 목록 조회
- 페이지네이션 (20개씩)
- 검색 기능 (상품명, 브랜드)
- 필터링 (카테고리, 가격대, 재고 상태, 활성 상태)
- 정렬 (최신순, 가격순, 재고순)
- 일괄 작업 (선택 삭제, 활성화/비활성화)

3.2 상품 등록 (`/admin/products/new`)
- 상품 기본 정보 (이름, 브랜드, 설명)
- 가격 정보 (가격, 할인율)
- 카테고리 선택 (계층형 카테고리)
- 이미지 업로드 (대표 이미지 + 추가 이미지)
- 재고 관리 (재고 수량)
- 활성화 상태 설정
- 폼 검증 (Zod 스키마)

3.3 상품 수정 (`/admin/products/[id]/edit`)
- 모든 상품 정보 수정
- 이미지 교체 및 추가
- 수정 이력 추적 (updatedAt)

3.4 상품 삭제
- 소프트 삭제 (isActive = false) 또는 하드 삭제
- 연관된 장바구니 아이템 및 주문 아이템 고려
- 삭제 확인 모달

**데이터 검증**:
- 가격은 0 이상
- 할인율은 0-100%
- 재고는 0 이상
- 이미지 URL 형식 검증

### 4. 주문 관리 (Order Management)
**경로**: `/admin/orders`

**기능 목록**:
4.1 주문 목록 조회
- 페이지네이션
- 검색 (주문번호, 고객명, 전화번호)
- 필터링 (주문 상태, 날짜 범위, 가격 범위)
- 정렬 (최신순, 금액순)

4.2 주문 상세 조회 (`/admin/orders/[id]`)
- 주문 기본 정보 (주문번호, 주문일시, 상태)
- 고객 정보 (이름, 이메일, 전화번호)
- 배송 정보 (배송지 주소, 수령인)
- 주문 상품 목록 (상품명, 수량, 가격)
- 결제 정보 (총 결제 금액)
- 주문 타임라인 (상태 변경 이력)

4.3 주문 상태 관리
- 상태 변경 (PENDING → PAID → PREPARING → SHIPPED → DELIVERED)
- 취소/환불 처리 (CANCELLED, REFUNDED)
- 상태 변경 시 알림 발송 (이메일/SMS)
- 배송 추적번호 입력

4.4 주문 통계
- 상태별 주문 수
- 기간별 매출 분석
- 고객별 주문 이력

**비즈니스 로직**:
- 특정 상태에서만 다른 상태로 변경 가능 (상태 머신)
- 취소/환불 시 재고 복구
- 배송 완료 후 7일 뒤 구매 확정

### 5. 카테고리 관리 (Category Management)
**경로**: `/admin/categories`

**기능 목록**:
5.1 카테고리 트리 조회
- 계층 구조 표시 (대분류 > 중분류 > 소분류)
- 레벨별 표시 (level: 1, 2, 3)
- 상품 수 표시

5.2 카테고리 생성
- 카테고리명, 슬러그, 설명
- 부모 카테고리 선택 (계층 구조)
- 레벨 자동 계산

5.3 카테고리 수정/삭제
- 카테고리 정보 수정
- 하위 카테고리 처리 (재할당 또는 함께 삭제)
- 연관된 상품 처리 (카테고리 변경 또는 미분류 처리)

**제약사항**:
- 최대 3단계 계층
- 슬러그는 고유값
- 하위 카테고리가 있는 경우 삭제 불가 (하위 먼저 삭제 또는 이동)

### 6. 사용자 관리 (User Management)
**경로**: `/admin/users`

**기능 목록**:
6.1 사용자 목록 조회
- 페이지네이션
- 검색 (이름, 이메일, 전화번호)
- 필터링 (역할, 가입일)
- 정렬 (최신 가입순, 이름순)

6.2 사용자 상세 조회 (`/admin/users/[id]`)
- 기본 정보 (이름, 이메일, 전화번호, 주소)
- 역할 정보 (USER/ADMIN)
- 가입일, 최종 수정일
- 주문 이력 (총 주문 수, 총 구매 금액)
- 리뷰 목록

6.3 사용자 관리
- 역할 변경 (USER ↔ ADMIN)
- 사용자 정보 수정
- 계정 비활성화/삭제

6.4 관리자 계정 생성
- 이메일/비밀번호 방식
- 초기 비밀번호 설정
- 역할을 ADMIN으로 설정

### 7. 리뷰 관리 (Review Management)
**경로**: `/admin/reviews`

**기능 목록**:
7.1 리뷰 목록 조회
- 페이지네이션
- 검색 (상품명, 사용자명)
- 필터링 (평점, 날짜)
- 정렬 (최신순, 평점순)

7.2 리뷰 상세 조회
- 리뷰 내용, 평점, 이미지
- 작성자 정보, 상품 정보
- 작성일

7.3 리뷰 관리
- 부적절한 리뷰 삭제
- 리뷰 승인/거부 (선택 사항)

### 8. 통계 및 리포트 (Statistics & Reports)
**경로**: `/admin/reports`

**기능 목록**:
- 매출 리포트 (일간/주간/월간/연간)
- 상품별 판매 통계
- 카테고리별 매출
- 사용자별 구매 패턴
- 재고 현황 리포트
- CSV/Excel 내보내기

### 9. 시스템 설정 (System Settings)
**경로**: `/admin/settings`

**기능 목록**:
- 사이트 기본 정보 (사이트명, 로고, 파비콘)
- 배송 정책 설정
- 반품/환불 정책
- 개인정보 처리방침
- 이용약관
- 이메일 설정 (SMTP)
- 알림 설정

## UI/UX 요구사항

### 레이아웃
- 사이드바 네비게이션 (접을 수 있음)
- 상단 헤더 (사용자 정보, 로그아웃, 알림)
- 브레드크럼 네비게이션
- 반응형 디자인 (모바일, 태블릿, 데스크톱)

### 디자인 시스템
- Radix UI 컴포넌트 활용
- Tailwind CSS 유틸리티 클래스
- 다크 모드 지원 (선택 사항)
- 일관된 색상 팔레트 (primary, secondary, success, danger, warning)

### 사용자 경험
- 로딩 상태 표시 (스켈레톤, 스피너)
- 에러 처리 (토스트 알림)
- 성공/실패 피드백
- 확인 모달 (삭제 등 위험한 작업)
- 폼 검증 실시간 피드백

## 성능 요구사항
- 페이지 로드 시간 < 2초
- 리스트 페이지 페이지네이션 (무한 스크롤 선택 사항)
- 이미지 최적화 (Next.js Image 컴포넌트)
- Redis 캐싱 (대시보드 통계, 자주 조회되는 데이터)
- 데이터베이스 쿼리 최적화 (인덱스, N+1 문제 해결)

## 보안 요구사항
- HTTPS 사용
- CSRF 보호
- XSS 방지 (입력 검증, 출력 이스케이프)
- SQL Injection 방지 (Prisma ORM 사용)
- 비밀번호 암호화 (bcryptjs)
- 세션 관리 (세션 타임아웃, 세션 하이재킹 방지)
- API Rate Limiting (선택 사항)

## 데이터베이스 스키마 활용
**기존 모델**: User, Account, Session, Category, Product, Cart, CartItem, Order, OrderItem, Review

**필요한 추가 스키마** (선택 사항):
- AdminLog (관리자 활동 로그)
- SystemSetting (시스템 설정)
- EmailTemplate (이메일 템플릿)

## API 엔드포인트 (Server Actions 또는 Route Handlers)

### 상품 API
- GET /api/admin/products (목록)
- GET /api/admin/products/[id] (상세)
- POST /api/admin/products (생성)
- PUT /api/admin/products/[id] (수정)
- DELETE /api/admin/products/[id] (삭제)

### 주문 API
- GET /api/admin/orders (목록)
- GET /api/admin/orders/[id] (상세)
- PATCH /api/admin/orders/[id]/status (상태 변경)

### 카테고리 API
- GET /api/admin/categories (목록)
- POST /api/admin/categories (생성)
- PUT /api/admin/categories/[id] (수정)
- DELETE /api/admin/categories/[id] (삭제)

### 사용자 API
- GET /api/admin/users (목록)
- GET /api/admin/users/[id] (상세)
- PATCH /api/admin/users/[id]/role (역할 변경)
- DELETE /api/admin/users/[id] (삭제)

### 대시보드 API
- GET /api/admin/dashboard/stats (통계)

### 리뷰 API
- GET /api/admin/reviews (목록)
- DELETE /api/admin/reviews/[id] (삭제)

## 개발 우선순위

### Phase 1: 기반 구축 (필수)
1. 인증 시스템 (NextAuth 설정, 미들웨어)
2. 관리자 레이아웃 (사이드바, 헤더)
3. 관리자 대시보드 (기본 통계)

### Phase 2: 핵심 기능 (필수)
4. 상품 관리 (CRUD)
5. 주문 관리 (조회, 상태 변경)
6. 카테고리 관리 (CRUD)

### Phase 3: 추가 기능 (중요)
7. 사용자 관리
8. 리뷰 관리
9. 통계 및 리포트

### Phase 4: 고도화 (선택)
10. 시스템 설정
11. 이메일 알림
12. 활동 로그

## 테스트 요구사항
- 각 CRUD 기능 수동 테스트
- 권한 검증 테스트 (비관리자 접근 차단)
- 폼 검증 테스트
- 에러 처리 테스트
- 성능 테스트 (대용량 데이터)

## 제약사항 및 주의사항
1. **기존 데이터 보존**: 기존 사용자 데이터, 상품 데이터는 절대 변경/삭제하지 않음
2. **기존 기능 보존**: 사용자용 페이지 (/products, /, 등)는 수정하지 않음
3. **독립적 개발**: 관리자 페이지는 /admin/* 경로에만 구현
4. **환경 변수 보존**: .env 파일의 기존 설정 유지
5. **Docker 환경**: 모든 개발은 Docker 컨테이너 내에서 수행

## 성공 기준
1. 관리자 로그인 후 대시보드 접근 가능
2. 상품 CRUD 모든 기능 정상 작동
3. 주문 목록 조회 및 상태 변경 정상 작동
4. 카테고리 계층 구조 관리 정상 작동
5. 비관리자 접근 시 자동 차단
6. 모든 페이지 2초 이내 로드
7. 모바일/태블릿에서 정상 작동
